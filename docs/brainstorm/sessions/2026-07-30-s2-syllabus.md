## 🔴 The defect: two different "syllabus covered" percentages

| | Admin board | Parent portal |
|---|---|---|
| Denominator | **planned** topics | **all** topics in the syllabus |
| Numerator | distinct logged topics, partial = **0.5** | topics with any log, partial = **1** |
| Source | `insights/syllabus.py` ← `forecast_org` | `GrowthService` chapter roll-up |

A parent and a principal read different numbers for the same subject on the same day, and
neither is wrong on its own terms.

**This is the second instance of the same defect class** — session 1 found three definitions of
"absent for a day". It will keep happening until *one computation, many renderings* is enforced
as a build rule rather than listed as a principle.

## What else the review turned up

1. **No trend.** Everything is as-of-today; nobody can tell a month-long slide from a bad week.
2. **Behind and unrecorded look identical.** `logged_periods` is computed and used *only* as a
   ranking guard — a teacher who never logs topics reads as *behind*. Attendance solved exactly
   this with the capture heatmap; syllabus has no equivalent.
3. **No "why".** The screen stops precisely where the admin's work starts.
4. **The rank score is unexplainable** (`on_track × 60 + coverage × 40`) — and it is about people.
5. **The best thing in the module is buried** — the exam checkpoint answers the question schools
   actually manage against, behind a tab.

## The quick-action question, answered

The founder asked directly whether quick actions make sense here, having not thought of any.

**They didn't come to mind because most syllabus problems are not one-tap solvable.** Attendance
produces "call this parent" — a complete action. A subject three weeks behind produces a
conversation and a re-plan. A fake quick action would be worse than none, because it implies the
problem is closed.

Three are real, and one is genuinely *the* action:
- **Size these chapters** — a deep link for `unestimated`/`unplanned` rows. Highest yield.
- **Ask for a catch-up plan** — creates a task on the teacher with the gap prefilled. This is
  what an admin actually does, and unlike a status change it produces a reply.
- **Schedule new chapters** — `extend_plan`, already built, currently buried.

## The idea worth keeping from this session

**`S-41` — say *why* it's behind.** Four causes, four different responses: periods were lost ·
nothing was logged · chapters were never sized · genuinely slower than planned. Almost all the
data already exists.

*"6-B Maths is 3 weeks behind"* → *"6-B Maths lost 8 periods to exam week and two holidays"*.
Different conversation, and often one in which nobody is at fault. This is what turns the board
from a scoreboard into a diagnosis, and it is the strongest idea to come out of either session.

## `D-13` — parent login by school code + date of birth

School code → class → section → child → **DOB as the password**, session until logout. Replaces
phone-OTP as the primary path and answers `Q-22`.

**Two fields do not exist** *(verified)*: `organizations` has no school code, and `students` has
no date of birth — nor does the roster importer map one. So this cannot ship until DOB is
collected for every student, and **a student without a DOB has a parent who can never log in**
(`Q-24`).

**Two security facts, recorded so they are accepted rather than discovered.** Neither blocks the
design — the pattern is common in Indian school apps — and each has a fix that keeps the UX
identical:

1. **The picker is a roster leak.** Code → class → section returns every child's name *before*
   any password. Fix: `S-55` — type-to-search, not a browsable list.
2. **A DOB is ~5,500 guesses**, and the picker names the target. Fix: `S-56` — reuse the OTP
   module's 5-attempt lock and hourly throttle, keyed per student.

**And the quiet one:** today a single phone links *all* guardian rows, which is how siblings roll
up into one session. Per-student DOB login breaks that (`Q-25`).

## `D-15` — syllabus visibility, and a Claude recommendation overruled

Subject teacher: her own subjects only, **blocked** — not merely defaulted away from. Class
teacher: all subjects and all teachers' pace, **but only for her own class**.

Claude had argued against blocking (`Q-17`), on the grounds that hiding a coverage figure between
colleagues invites the belief it is being used against them. Overruled; `S-52` marked REJECTED
and the screens updated. Recorded here because a rejected suggestion that stays visible is the
point of the tag system.

## `D-16` — the catch-up action, and what it implies

*"Ask for a catch-up plan"* approved. **Direct admin rescheduling rejected** — a plan change
should come out of a discussion between the teacher and the principal, not a button on a board.

That makes the button a **meeting request, not a directive** (`S-60`), with a consequence worth
noticing: the row clears when the **outcome** of the meeting is recorded, not when the task is
created.

**Which is the same shape as attendance's follow-up** (`S-21`): a request → a conversation → an
outcome. Two modules now want the same primitive, and `followup_actions` already exists and
records only the press. Worth generalising once (`S-59`) rather than building it twice with
different words.
